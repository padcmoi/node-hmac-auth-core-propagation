First release. The package is the credential propagation layer extracted from the
deprecated `@naskot/node-hmac-auth` 1.x. It consumes `@naskot/node-hmac-auth-core`
as a peer dep and drives RabbitMQ internally.

## What's in the box

- `createPropagator(options)` factory returning a `Propagator` instance.
- High-level helpers `ensure`, `rotate`, `revoke`, `sync`, `close`.
- Two modes selected by the presence or absence of `options.management`:
  - **Receive-only** (no management): apply inbound events locally via the core lib,
    publish the return ACK best-effort.
  - **Full mode** (8 callbacks): in addition, the peer drives credentials and
    propagates them to known targets.
- AMQP via `amqplib` 0.10.4+. Vhost default `hmac-credentials`. One durable queue per
  peer named `hmac-<amqpQueue>.queue`. Prefetch 1. Publisher confirms enabled.
- Redis-backed monotonic cursor and ack store. The interface is a small camelCase
  surface compatible with node-redis v4+.
- 14 error codes via `HmacPropagationError`.

## Wire contract

Pinned at v1, byte-identical for the whole `1.x` line. See
[wire-contract.md](../wire-contract.md).

## SQL schema reference

The lib does not ship a schema; it requires the callbacks to honor the contracts.
A 4-table reference for MariaDB with `ON DELETE RESTRICT` everywhere is documented in
[sql-schema.md](../sql-schema.md). TypeORM entities + a NestJS module are in
[entities-nestjs.md](../entities-nestjs.md).

## Migration from `@naskot/node-hmac-auth` 1.x

If you were using the propagation features of the deprecated upstream (the
`internalManagementRoute`, `requireBootstrapClientId`, `propagateClientToApis`,
the `propagation-only` purpose), the mapping is:

| Upstream `@naskot/node-hmac-auth` 1.x                 | This lib                                                         |
| ----------------------------------------------------- | ---------------------------------------------------------------- |
| `auth.propagateClientToApis(...)`                     | `propagator.ensure(...)` then `propagator.sync()` from a cron    |
| `auth.createExpressInternalManagementMiddleware()`    | gone. The lib drives RabbitMQ; no HTTP route is needed.          |
| `auth.handleInternalManagementRequest(...)`           | gone.                                                            |
| `internalManagementRoute`, `requireBootstrapClientId` | gone.                                                            |
| `purpose: "propagation-only"`                         | gone. The cantonment is implicit: propagation lives in this lib. |
| `fromDbSeed: true` on `setSecret`/`setSecretHash`     | gone. The TTL backup is unconditional in the core.               |

The HMAC verifier behavior is unchanged. Code that only signed and verified
requests (no propagation) migrates by renaming the import to
`@naskot/node-hmac-auth-core` and dropping any propagation options.
